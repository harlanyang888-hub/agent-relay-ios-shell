# 手机原生日志上报

1.0.48（49）开始复用现有 `/api/client-diagnostics`，不新增公开日志入口。
手机从已有 WKWebView Cookie 存储取得登录凭据，启动时同步一次，登录 Cookie 变化时更新。
日志记录不读取或初始化录音服务，避免重入初始化。只上传状态日志，不上传录音、Cookie 或消息正文。

有新日志时约三秒合并发送，活动期间五秒检查补传；失败退避三十秒。
发送时申请短期后台时间。系统挂起、强退、断网、VPN 不通或登录过期时不能保证实时性。
本地仍保留最近 250 行，恢复后发送快照。服务端沿用鉴权、脱敏及报告数量/有效期限制。

从开发电脑读取最近一次 iOS 上报：

```sh
python tools/read_phone_diagnostics.py --lines 150
```

读取通过已有 SSH 身份直接访问服务端报告目录，默认严格校验已知 SSH 主机密钥。
结果带报告接收时间、App 版本及进程 runId，排查时先检查时效，不能把旧报告当作当前状态。

## 本次实机证据

串口 COM4 捕获两次 BOOT 长按：`encrypted=0 subscribed=1 ready=0`。
说明按键检测工作，但手表尚未进入加密就绪状态，固件阻止发送录音命令。
保留 NVS 和配对信息重启手表后，观察窗口尚未捕获手机重连，仍需手机端配合。
手机包增加受保护身份读取的有限重试，并分别展示加密认证和通知状态。
这不代表已验证自动恢复成功，也不解决此前双蓝牙设备的麦克风路由问题。
