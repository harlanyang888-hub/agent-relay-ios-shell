# 电量与续航开发计划

日期：2026-11-19。用户已多次实测认可 1.0.49 (50) 配套固件的录音流程；本阶段保持该控制协议和会话语义。

## 基线与判断

当前只初始化 BLE、按键和马达，不初始化 Wi-Fi、显示、音频；主任务每 10ms 轮询按键。没有专门配置动态调频、自动轻睡眠或 PMIC 外设电源管理。因此功能负载较轻，但不能称为已优化的低功耗固件；实际整表平均电流和续航未知。

按需显示时间预计比常亮表盘省电；短时电量读取/BLE 通知增量预计较小；播报若由手机完成，手表增量更小。本地采音涉及麦克风 ADC、I2S、存储及可选编码；持续 Wi-Fi 涉及射频与网络重连，均须独立测量。禁止把射频峰值电流当作整表平均电流，禁止直接相加各功能平均值。

## 开发顺序

1. 只读接入 AXP2101：确认官方驱动及寄存器，读取电池存在、电压、估算百分比、USB/充电状态；不可用时返回未知，先不改充电参数及电源轨。
2. 添加 BLE 电量读取和订阅，与录音控制消息分离。建议待机每 60 秒采样、百分比变化或充电状态变化再通知；重连立即读取。手机显示时间戳和断连/过期状态。后台投递为尽力而为，重连补读。
3. 记录放电基线：固件版本、电池标称容量、起止电量/电压、USB 状态、时长、按键/震动次数、连接/重连次数、屏幕/Wi-Fi/音频开关。正常使用耗尽测试与外部电流测量分开记录。USB 插线读数不能当作纯电池放电结果。
4. 逐项优化并对照：按键事件唤醒、CPU 调频、BLE 连接/广播参数、控制器睡眠、闲置外设电源。每项都复测锁屏触发、长时间闲置、断连重连与掉电恢复；未经验证不启用会断 BLE 的深睡。
5. 最小正式界面：手机显示电量/充电/连接/录音状态及待发数量；手表按需亮屏显示时间、电量与录音状态，自动息屏。复用既有按键语义。
6. 可选扩展逐项立项：本地录音、Wi-Fi 批量上传、扬声器播报。每项均测启用时平均电流、单次事件耗电及每日占空比。

## Tailscale 决策

ESP-IDF 没有可直接安装的官方 Tailscale 客户端；存在社区 ESP32 兼容实现，但不等于已在本板和现有 NimBLE 固件验证。现阶段维持手表 BLE → 手机 → 服务端，VPN 在手机/网关处理。独立 Wi-Fi 联网若未来需要，优先评估短时 HTTPS 上传或局域网代理；仅在必须让手表成为 tailnet 节点时单独验证社区协议栈、内存、密钥、兼容性和功耗。WireGuard 实现不等同于完整 Tailscale。

## 验收与记录

- 电量读取失败不阻断录音，不伪造 0% 或旧值为新值。
- 不清空配对/NVS，不变更录音命令格式；升级后回归原四种手势。
- 首版目标是有可信电量与基线，不承诺尚未测得的小时数或节电比例。
- 每个实验只改变一个主要因素，记录平均电流/消耗电量及操作延迟；百分比只用于粗估，精确能耗需外部仪表。
