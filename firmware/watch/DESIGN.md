# 手表与手机录音设计

## 职责

手表负责按键、蓝牙和震动。iPhone 负责录音、文件保存、会话和上传。手表不采集音频，不通过 Wi-Fi 上传。

手机代码以 v1.0.33-user-approved-ble-recovery 为基线，保留 ASK 授权、CoreBluetooth 状态恢复和 LCK 系统音频激活路径。

## 系统会话与音频通路

LCK 管理系统语音会话，并在系统激活音频后启动采集；AVAudioRecorder 把手机实际输入写为 AAC 文件，之后上传网关。当前没有把实时音频通过 RTP、WebRTC 或 SIP 发送给远端。使用系统通话会话与保存录音文件可以同时成立。

认可版本使用 playAndRecord、voiceChat，同时允许 Bluetooth HFP 和 A2DP。HFP 是蓝牙音频输入通路，A2DP 是蓝牙音频输出通路；允许某个通路不等于实际选中它。以 currentRoute.inputs 和实际采样诊断判断输入设备。手机内置麦克风不因为允许 HFP 就自动成为 8kHz 蓝牙输入。

不设置“严禁 allowBluetooth”的全局规则，这会改变外接蓝牙麦克风的可用性。蓝牙麦克风音质按实际协商结果验证，不承诺所有 HFP 都是 8kHz，也不把 AAC 文件编码采样率当成采集链路带宽。暂停或发送后的微信音频兼容性另行实测。

输入选择是向系统发出的偏好请求。录音器准备后可再次请求路由，实际输入以 currentRoute 和采音诊断为准。不得在录音器启动前因输入偏好未立即匹配而用固定两秒超时终止整个会话；未匹配时显示实际输入和提示。设备不可用、录音器启动失败与采音中断仍分别报告。

暂停和发送后结束系统通话，继续录音时重新请求 LCK 激活。Agent 逻辑会话独立保存，因此同会话发送不依赖一直保留一个空闲系统通话。PWR 结束操作同时关闭逻辑会话，使下一条进入新的 Agent 对话。

Apple 说明 voiceChat 模式本身会自动应用 allowBluetoothHFP。因此保留 voiceChat 时，不能把删除显式 allowBluetooth 当作禁止 HFP 的实现。参考：https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/voicechat

## 操作

| 操作 | 手机实际状态 | 结果 |
| --- | --- | --- |
| BOOT 长按 | 无录音草稿 | 开始录音；沿用未结束的逻辑会话，否则新建 |
| BOOT 长按 | 正在录音或已暂停 | 保存并发送本条；保留逻辑会话 |
| BOOT 短按 | 正在录音 | 暂停，保留草稿 |
| BOOT 短按 | 已暂停 | 继续同一草稿 |
| BOOT 短按 | 无草稿 | 不启动录音 |
| PWR 长按 | 任意状态 | 保存有效草稿并发送，结束逻辑会话及系统会话 |

长按暂定 1.2 秒，触发后释放不再产生短按。PWR 的硬件关机行为保持；不依赖硬件关机前一定有机会完成上传。

## 状态与确认

蓝牙连接、系统语音会话、Agent 会话、录音草稿和上传状态分别保存。暂停录音不等于结束草稿；文件已保存不等于服务器已收到；系统会话结束不自动删除未上传文件。

手机是录音状态的唯一来源。手机启动时更换 epoch，每次状态变化增加 revision。手表每次重连先同步，再携带 epoch 和 revision 发操作。手机校验状态后原子地决定开始、暂停、继续或发送；旧状态操作只返回新快照，不执行。

每次操作有启动随机数和序号。重传保持同一标识。手机去重并缓存结果，丢失确认时不能再次产生录音或消息。一次最多处理一个操作，不积压开始和结束事件。过期、断线和忙时按键有失败反馈。

开始成功以实际采音帧增长为准。暂停成功以采集已暂停为准。发送反馈分为本地保存和服务器接收；震动模式须实机确认能区分。超时后显示未知并同步，不把未知解释为待命。

## 录音文件

暂停期间不写入静音。每次暂停封口保存当前段，继续时创建下一段；发送时按顺序合并为一条 16kHz 单声道 AAC 文件，验证可解码、有效时长和段次序。

草稿 manifest 保存段顺序、文件路径、有效采音时长、逻辑会话和目的地。段文件验证完成后再加入 manifest。发送时合成单条音频并验证可解码、时长和顺序。暂停时间必须从现有墙钟时长检查中扣除。

进程终止或掉电后，把已完成的段恢复为中断草稿；正在写入的尾段需验证，不能承诺一定完整。不得自动恢复麦克风采集或把中断草稿默认为已发送。

## 网络与发件箱

创建系统语音会话和手机录音不以网关请求成功为前提。发送依赖网关实际可达；配置为 Tailscale 路由时需 VPN 可用。

发送前将音频、消息 UUID、目的地、逻辑会话 ID 和顺序持久化。网络错误、未登录和进程重启不删除待发文件。网络可用且 App 获得执行机会时重试；网络路径可用不代表网关可达，也不保证已终止的 App 会被唤醒。

服务端按消息 UUID 去重，并将客户端逻辑会话稳定映射至同一 Agent 会话。第一条离线消息尚未创建服务器会话时，后续消息不能各自创建新会话。结束会话后，旧上传回调不能覆盖新会话 ID。

上传前查询网关补传能力。确认支持后，消息携带固定 Idempotency-Key 和 logicalSessionId；网关持久保存会话映射和接收结果，重试返回原结果。若网关已有投递占位但结果不明，返回 voice_result_uncertain，手机保留文件并停止自动重发。旧网关没有去重能力时，不盲目重试结果不明的上传。

服务器确认持久保存附件和消息后，才标记送达。附件可用与 Agent 已处理分别展示。磁盘满、合并失败、认证过期需要明确反馈和恢复入口。

## 蓝牙与掉电恢复

设备身份和配对密钥保存在 NVS。普通重启、断电和固件更新不清除；恢复出厂配对使用明确独立操作。加密 GATT、固定应用 UUID 和持久化蓝牙身份各自验证。

手表开机及断线后广播，由手机中心连接；正常恢复不弹 ASK 添加框。持续数小时离线、手机使用其他 App、手表耗尽电量和重新上电都要验证。不能用短时休眠结果替代长时间掉电测试。

## 验收顺序

1. 备份出厂 Flash，确认 BOOT、PWR、马达与供电。
2. 加密配对、状态同步、手机侧开始录音、发送。
3. 多次暂停和继续，合成一条消息；同会话与新会话边界。
4. 丢确认、重复包、过期包、快速按键、手机端手动结束与中途掉电。
5. 断网、VPN 关闭、认证过期、上传中断、重启补发及服务端去重。
6. 多小时离线与完全断电后自动恢复，锁屏及进程恢复。
7. 微信语音、麦克风、来电和系统中断兼容性。
